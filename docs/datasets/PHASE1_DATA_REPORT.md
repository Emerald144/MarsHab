# TerraNexis Phase 1: Jezero terrain data

Real terrain measurements for the 8 georeferenced Jezero study zones (JZ-01 to JZ-08), taken from the USGS CTX DEM. Everything here is generated by `scripts/run_all.bat`. None of the original files or the app were modified, and nothing was committed to git.

**Status:** all 12 automated QA checks pass (`metadata/validation_report.json`).

## B. NASA/USGS sources (verified)

- **CTX DEM.** USGS Astrogeology, *Mars 2020 Science Investigation CTX DEM Mosaic* (published 2021-10-14), file `M20_JezeroCrater_CTXDEM_20m.tif`. The product page is <https://astrogeology.usgs.gov/search/map/mars_2020_science_investigation_ctx_dem_mosaic>. USGS says it was built with Ames Stereo Pipeline and vertically tied to MOLA. The local file's name, size (~87 MB), CRS and extent match. Checksums were not compared against the USGS server.
- **CTX orthomosaic (recommended, not downloaded).** `M20_JezeroCrater_CTXortho_mosaic_5m.tif` from the same USGS product, at 5 m. The hillshade stands in as the basemap for now.
- **Geologic map (optional, not prepared).** USGS SIM 3464, Sun & Stack, *Geologic Map of Jezero Crater and the Nili Planum Region, Mars*, public domain, <https://pubs.usgs.gov/publication/sim3464>. It ships as a ~349 MB Esri file geodatabase in a different projection.
- **Perseverance images (optional, not prepared).** The local PDS PLACES tables give rover positions, but no image set with verified footprints was linked to zones.

## C. Processing summary

- **CRS.** Everything is in `Jezero_Crater_Projection`: Equidistant Cylindrical, lat_ts 18.4663°N, lon_0 0, on the Mars 2000 sphere (R = 3,396,190 m). Units are metres, longitude is east-positive, and latitude is planetocentric (the same as planetographic on a sphere). The zones' CRS matches the DEM's. No Earth CRS is used anywhere. The only transform applied is the projected-to-Mars-lon/lat inverse on the same sphere, done with PROJ. See `metadata/spatial_reference.json`.
- **Slope.** The existing raster was validated against GDAL `DEMProcessing` slope (Horn 3×3, scale = 1, since horizontal and vertical units are both metres). It matched exactly, so it is reused and no new slope raster was written. The east–west scale error of the projection inside this DEM is within ±1%.
- **Hillshade (new).** GDAL Horn, azimuth 315°, altitude 45°, Byte DEFLATE, 13.6 MB. Display only.
- **Elevation clip:** not created. All zones lie inside the DEM, so a clip would only duplicate the 86 MB original.
- **Zonal statistics.** Each polygon is rasterised to the 20 m grid using the pixel-centre rule, and NoData is excluded. Coverage is valid pixels divided by in-polygon pixels. Area is given two ways: planar-projected, and spherical (geodesic on the Mars sphere).
- **Slope classes.** Configurable in `scripts/config.json`: gentle ≤5°, moderate >5–15°, steep >15°, plus % above 10/20/30°. These are analysis categories, not safety limits.

## F. Validation report

All 12 checks pass. They cover: valid geometries, unique IDs, overlap with the raster (8/8 fully inside), CRS and grid alignment, NoData excluded, finite elevations, slope within 0–90° (and validated), area units (projected, spherical and pixel-count methods agree), JSON ↔ CSV match, provenance, web-layer bounds ↔ vectors, and no fabricated values. The last check also confirms that the slope means reproduce the earlier QGIS stats.

**Unresolved issues (not failures):**
- Maximum slopes of 75–88° at 20 m most likely include stereo-DEM artefacts and crater-wall edges. Use `p90`/`p99` and the class percentages in place of `max`.
- A faint north–south seam is visible in the DEM floor, inside JZ-07 near x ≈ 4.376e6.
- The zones are large geometric partitions with straight edges (the metadata calls them "reconstructed"), not geologic units.

## G. Integration guide (for the frontend developer)

1. **Zones on the existing SVG map.** The app's `Zone.points` is an SVG polygon string. Use `vectors/jezero_zones_preview_pixels.json`, which holds `zones[].svg_points[0]` and `center` in a 1114 × 1267 pixel space that matches the preview PNGs. Render one of the PNGs as `<image width=1114 height=1267>` and use `viewBox="0 0 1114 1267"`, or scale to the app's 1000 × 680 box with one uniform scale factor. The aspect ratio differs, so letterbox; don't stretch.
2. **Zone IDs.** These are `JZ-01` to `JZ-08`. They replace the illustrative `A-12` to `A-19`, which are not real geometries.
3. **Statistics.** Join `statistics/zone_terrain_statistics.json` `zones[]` on `zone_id`. For example:
   ```json
   {"zone_id":"JZ-07","area_km2_spherical":401.776,"centroid_lon_lat_deg":[77.843251,18.704522],
    "elevation_m":{"min":-2624.997,"max":-1898.057,"mean":-2303.274,"range":726.939,"coverage_percent":100.0},
    "slope_deg":{"mean":4.28,"median":3.208,"std":3.987,"p90":8.366,"p99":20.39,"max":81.538},
    "slope_class_percent":{"gentle":73.29,"moderate":23.861,"steep":2.848},
    "terrain_screening":{"dominant_slope_class":"gentle","heuristic_terrain_index":85.2},
    "data_quality_flags":[]}
   ```
4. **Terrain factor.** If the app needs `factors.terrain` (0–100), a documented option is `terrain_screening.heuristic_terrain_index`. Label it "heuristic, slope-only". The other factors (resource, access, env, science) still have **no real data** and stay as they are.
5. **Layer switching.** Read `web_layers/layer_manifest.json`. Each `raster_layers[]` entry has `id`, `name`, `path`, `bounds` (projected metres and Mars lon/lat), `width_px`/`height_px`, the source and display pixel sizes, and a `legend` (continuous stops, or categorical classes with hex colours). Copy the PNGs into `public/` when integrating.
6. **Globe / geographic map.** Use `vectors/jezero_zones_mars_lonlat.geojson` together with `mars_lon_lat_deg` bounds. The PNGs are equirectangular, so they drape directly between those bounds. These are **Mars** degrees: never pass them to an Earth basemap, or to any projection that assumes EPSG:4326 means Earth.
7. **Don't** serve the `.tif` files to the browser.

## I. Limitations

- **Real measurements:** CTX DEM elevations (USGS).
- **Derived measurements:** slope, hillshade, the zonal statistics, and the class percentages.
- **Heuristic:** `heuristic_terrain_index` and the existing `Jezero_Terrain_Cost.tif`.
- **Project-defined:** the zone boundaries themselves.
- **Not measured:** boulders, regolith looseness, sand, surface stability, and any astronaut safety threshold.
- **Elevations** are relative to the Mars datum used by USGS. They are not re-verified here.
